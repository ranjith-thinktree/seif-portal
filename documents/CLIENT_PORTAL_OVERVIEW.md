SEIF Portal — Client Overview (easy-to-read)

Purpose

This document explains, in simple words, what the SEIF Portal does and how people will use it. Share this with stakeholders who are not technical. Use it to check the flows and tell us what to change.

Who uses the portal

- Partner: An organization that uploads training center data, including batches and student details. Each partner manages multiple centers.
- Admin: SEIF system administrators who review and approve uploaded data, handle requests, and can request partners to upload specific center data.
- SEIF HQ: A read-only team that looks at reports and exports.

What the portal does (short)

- Lets partners upload center data with batch and student details (one CSV file per center).
- Keeps uploaded data in a safe staging area until an admin reviews it.
- Lets admins approve or reject entire uploads and send in-app notifications to partners with rejection reasons.
- Lets admins request partners to upload specific center data with scheduling options (immediate or recurring).
- Lets partners raise requests for refurbishment or data corrections with photos and notes.
- Stores an audit trail of important actions so we can see who did what.
- Provides simple read-only dashboards for SEIF HQ.

How a Partner will use the portal (step-by-step)

1. Sign in: Partner users log in with email and password.
2. Upload center data: Partners upload ONE CSV file per center containing center details, batch information, and all student records for that center. They fill in a simple form (center name, batch number, dates, student counts) and attach the CSV file.
3. Review: The portal stores the uploaded file in a review area and shows the upload status as "pending". Admin receives an in-app notification about the new upload.
4. Wait for admin review: Partner waits for the admin to review the entire upload.
5. Fix if rejected: If the admin rejects the upload, the partner sees an in-app notification with the rejection reason and remarks explaining what needs to be corrected. Partner modifies the CSV file and re-uploads (same upload record gets updated status).
6. Finalize: When the admin approves, the partner sees the approval notification in the portal and all data (center, batch, students) moves into the main database.
7. Refurbishment requests: Partner receives a refurbishment alert in their inbox when their center becomes eligible (based on how much time has passed since the last refurbishment). Partner clicks to view the alert, reviews the center details and available packages for each course (like Electrical, Solar, Industrial Automation), selects the items needed for each course, writes a brief explanation of why those items are needed, and uploads photos showing the current condition. If they need a room upgrade, they can optionally add room measurements (length, width, height) with photos and justification. Partner reviews everything in a preview screen and submits. Admin receives the submission and reviews it.

How an Admin will use the portal (step-by-step)

1. Sign in: Admin logs in with their account.
2. Inbox: Admin sees a list of pending uploads and requests in an admin inbox. When a partner uploads center data, admin receives an in-app notification.
3. Review data: Admin opens a pending upload, inspects all the center, batch, and student records from the CSV file.
4. Approve / Reject entire upload: Admin reviews the complete upload and either approves everything or rejects everything. If rejecting, admin provides a "reason for rejection" and "remarks" explaining exactly what needs to be fixed (e.g., "Student ID format incorrect in row 15"). Partner sees this in their notification.
5. Request partner uploads: Admin can request a partner to upload specific center data by selecting the partner, center name, providing a reason, and setting a schedule (immediate, monthly, quarterly, semi-annual, annual, or custom date range). The system automatically sends these requests at scheduled intervals.
6. Review other requests: Admin reviews refurbishment or support requests from partners, discusses internally (internal comments), and then marks a request approved or rejected.
7. Refurbishment management: Admin has a refurbishment dashboard with three main sections:
   - **Overview:** Shows which centers are eligible for refurbishment (based on time since last refurbishment or when the center was established), which centers were recently refurbished, and a complete list of all centers.
   - **Requests:** Shows active refurbishment requests. Admin can create a new refurbishment request by selecting an eligible center, choosing which courses to include (Electrical, Solar, etc.), and pre-selecting available packages for each course that the partner can choose from. Admin can add instructions or remarks for the partner.
   - **Past Requests:** Shows completed refurbishment requests (approved or rejected) with details of what was requested and admin's decision with remarks.
     When a partner submits their refurbishment selections, admin reviews the packages selected for each course, partner's justification, photos of current conditions, and optional room upgrade request. Admin can approve with remarks or reject with a detailed reason explaining what needs to be corrected.

Notifications (how partners/admins get updates)

- All notifications are in-app. When something important happens (upload received, row approved/rejected, request updated), a short message appears inside the portal.
- Notifications include a short title, a brief message, and a link to the item (upload or request) so the user can act quickly.

Files and formats — what we need from partners

- Center data uploads: ONE CSV file per center containing all center details, batch information, and student records. The CSV should have columns like: Partner Name, Partner ID, Center Name, Center ID, Batch No, Batch Start Date, Batch End Date, Student ID, Student Name, Date of Birth, Gender, Course Name, etc. We will share a detailed template showing exact column names and sample rows.
- Photos for refurbishment: JPG or PNG images showing current condition of equipment, rooms, or facilities. Partners upload these when selecting refurbishment packages for each course or when requesting room upgrades. Multiple photos can be uploaded per course.

Important user-facing states (what you will see)

- Pending: The uploaded data is waiting review.
- Approved: The data is accepted and available in the main system.
- Rejected: The admin rejected the row and included a reason. Partner can edit and re-upload.

Security and privacy (simple)

- Files are stored securely and only accessible by authorized users through the portal.
- We keep a log of important actions (who uploaded, who approved, and when) for accountability.
